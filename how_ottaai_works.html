How OttaAI chooses an AI key

A short guide to personal keys, workspace keys, the platform route, and what an organization admin can do.

Three key sources

Personal

My key

Used only for my requests.

Owner: the user
Bill: the user's provider account
Workspace

Our key

Available to people in the active workspace.

Owner: the organization
Bill: the workspace's provider account
Platform

Included AI

Set by the product operator, not a user.

Owner: the operator
Bill: the operator's provider account

Org admin: Admin → Growth → AI providers. “Everyone” creates the shared workspace key.

An organization admin can add both a workspace key and a separate personal key. They cannot create a personal key for someone else.

The default resolution order

The default strategy is user-then-org.

Important: if an admin has both a personal key and a workspace key, the admin's personal key wins for that admin under the default strategy. Other members can still use the workspace key.

What happens to a request

  1. 1
    Establish scope
    The server identifies the user, the active organization, and the app.
  2. 2
    Resolve a permitted key
    Only keys belonging to that user/workspace/app are considered.
  3. 3
    Apply the task rule
    A BYOK-required task does not fall back to the platform route.
  4. 4
    Apply cost controls
    If the platform would pay, a burst guard runs before the provider call.
  5. 5
    Call through AI Gateway
    The request leaves from the server; a saved key never reaches the browser.

What is protected

Keys

Write-only secrets

Keys are encrypted at rest and are never shown again after saving. Replacing a key means entering a new one.

Organizations

Server-side permissions

A workspace key needs ai:manage or org:admin. The browser cannot select another workspace by changing request data.

Platform spend

Fail closed

If platform rate limiting is unavailable or misconfigured, platform-paid calls stop before provider I/O. BYOK can continue.

What it is not

Not a billing quota

The platform control limits short bursts. It is not a monthly token allowance, invoice, or exact spend ceiling.

In one sentence

Users own personal keys, org admins manage shared workspace keys, and OttaAI resolves the best allowed source on the server—personal first, workspace second, platform last.
